# IMS 目标配置编辑器设计

## 目标与范围

让用户把 VoNR 等开关关闭后点击应用，系统收到明确的关闭配置；进入页面看到的是当前 CarrierConfig，而不是上次草稿。保留开关、快速预设、统一应用按钮，不新增逐项三态控制。这里的“启用”表示系统配置允许功能，不代表 IMS 已注册或网络当前提供该功能。

用户已同意先写设计和计划，再实现。范围包括读写映射、Shizuku 主路径和 Broker、逐卡结果、界面状态、历史和自动恢复兼容。不调整持久化 VoLTE、Captive Portal 和实际 IMS 能力查询。

## 已确认的系统约束

当前 `ImsModifier.buildBundle()` 只为开启项生成覆盖，关闭项被省略。AOSP CarrierConfigLoader 使用 `putAll` 合并临时覆盖；传入 `null` 清空该卡临时覆盖，不支持按键删除。覆盖调用在服务端排队，返回不等于回读已经一致。`getDefaultConfig()` 是框架通用默认值，不能作为当前运营商默认值。

参考：[CarrierConfigLoader](https://android.googlesource.com/platform/packages/services/Telephony/+/master/src/com/android/phone/CarrierConfigLoader.java)。本任务不通过先清空全卡覆盖来实现单项关闭，避免影响未编辑项目及其他工具的覆盖。

## 目标语义

- VoLTE、VoWiFi、漫游 VoWiFi、VoNR、VT、Cross-SIM、UT：关闭明确写入主控制键 `false`。开启保留必要的辅助配置；关闭不主动修改入口可见性键。系统可能因主能力禁用而自行隐藏入口，应用不保证其保持可见。
- 5G NR：开启配置 NSA、SA；关闭配置空可用性数组。读取时只要存在 NSA 或 SA 就显示开启，避免将仅支持其中一种的运营商误判关闭。
- 隐藏 LTE+、LTE 显示为 4G：对应布尔键明确写入目标值。Enhanced 4G LTE 不再隐式覆盖“隐藏 LTE+”。
- Enhanced 4G LTE：三个布尔键显式开启／关闭，不再关联 LTE+。
- 信号阈值、5G+ 规则：仅当系统提供完整且类型匹配的默认参数时支持关闭；关闭写回读取到的系统默认参数，界面注明不等同于运营商默认。
- 名称、IMS User Agent 等字符串，以及缺少完整默认参数的覆盖项：单独列入“自定义覆盖（恢复需重置）”，不通过空字符串或省略键伪装恢复；引导用户到高级工具执行已有的重置操作。
- 以上拆分由用户明确指定，不新增原值备份，也不为单项恢复清空全卡配置。
- Android 13 的 VoNR 和缺失配置键标为“不支持或无法读取”，不从 Feature 默认值推断当前状态。

## 数据与状态

新增纯 Kotlin 目标映射模型，集中定义每项主键、开启值、关闭值、读取规则及恢复类别。Android Bundle 只在桥接边界转换，便于独立验证映射。

每卡快照包含 subId、SIM 身份摘要、当前功能值和读取错误。未知值不能表示为关闭。编辑器保存本次选择、各卡快照、用户明确编辑的项目及读取/应用状态；实际读取值与待应用草稿分开。

普通单卡从实时快照初始化。所有 SIM 逐卡读取：共同值显示开关；不同值显示“各卡不同”，提供明确的启用、关闭选择；任一卡读取失败时不允许整批应用。批量页面仍不编辑字符串。应用只下发用户明确选择或预设指定的项，不将未编辑的混合状态或未知状态补成默认值。

显示值是概括状态，不用于判断完整目标是否满足。用户明确指定的预设、历史或恢复目标始终进入草稿；特权层按完整原始键判断是否需要写入。参数项另外提供“恢复系统默认参数”按钮，当前值来自其他工具时也能直接恢复。

页面重入和 Shizuku 重连均刷新系统基线，保留身份一致的有效草稿；读取失败保留草稿与原身份依据并禁止应用。确认身份变化或项目不再可读后才丢弃不安全目标。用户主动重新读取时确认放弃草稿。

## 特权事务

沿用主进程业务锁和 Instrumentation 串行锁。新协议与旧协议显式区分；主 Modifier 与 Broker 共用同一个目标操作 helper，避免两条路径语义漂移。

每张卡独立完成活动订阅/身份检查、读取、构造覆盖、写入、有限回读和结果返回。只有回读满足目标才算成功；失败返回原因并保留待应用意图。无活动 SIM 不算成功。批量成功卡保存自己的历史，失败卡不覆盖历史；不能显示一条笼统“全部成功”。切卡或新一轮读取后，旧异步结果不得覆盖新选择。

读取不依赖实际 IMS 能力查询；系统配置与 IMS 注册能力继续分别展示。操作中锁定编辑；重试保留失败目标。刷新以系统重新读取结果替换草稿，明确标为重新读取。

## 历史与自动恢复

历史增加配置语义版本。旧版 `false` 保持“不写入”的原语义，旧自动恢复仍走旧构造器。加载旧历史到编辑器只合并旧版会实际写入的项目，不把旧版关闭项升级为禁用指令。

新历史保存明确的、成功回读确认的目标意图；按卡保存，保留已有修订号、重置阻止标记和开机去重机制。自动恢复新历史使用新目标协议，也必须回读；一次失败不能污染其他卡。新旧历史合并时，只迁移旧版真实会写入的项目。

## 界面文案

- 顶部：“开关表示系统配置是否允许该功能，实际可用性请查看 IMS 状态。”
- 状态区：读取中／无法读取（重试）／已读取系统配置／有未应用的更改／已应用并核对／部分失败。
- 每项保留描述；参数类说明关闭恢复系统默认参数（非运营商默认），重置类单独分组并说明重置影响范围。
- 没有历史时提示，不自动填入推荐配置；推荐配置与历史加载仅改变草稿。

## 验收

1. VoNR 开启后关闭生成显式 false，回读失败不报成功。
2. 旧历史 false 不变成禁用；新历史 false 可自动恢复。
3. 所有 SIM 混合值不会被默认值覆盖；单卡失败有独立结果。
4. Shizuku 未就绪、权限拒绝、空结果、失效 SIM、缺键均不显示虚假开关状态。
5. 参数恢复值来自系统读取、不硬编码且不冒充运营商默认；重置类不接受空字符串或关闭恢复指令，不为单项操作清空全卡覆盖。
6. 针对纯 Kotlin 映射、合并和历史语义增加测试；运行现有单测、assembleDebug 和 lint。模拟器验证未知状态与布局；真实 Pixel/Shizuku 的写入回读单独列为设备验证，不用编译替代。
